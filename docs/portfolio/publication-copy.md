# نصوص جاهزة للنشر

استبدل صياغة دورك بما يطابق مساهمتك الفعلية قبل النشر. جميع الصور تستخدم بيانات خيالية؛ لا تعرض أسماء عملاء أو نتائج تشغيل حقيقية. لا تُرفق APK debug في معرض عام.

## مستقل — عنوان المشروع

بوابة المولدات — تطبيق Flutter عربي لإدارة القراءات والفواتير والتحصيل

## مستقل — وصف المشروع

تطبيق لإدارة العلاقة بين أصحاب مولدات الأحياء والمشتركين، يجمع حالة التشغيل والقراءات والفواتير والمدفوعات في واجهة عربية واضحة.

عملت على بناء تجربة متكاملة باستخدام Flutter وDart، مع Firebase للمصادقة والبيانات، وRiverpod لإدارة الحالة، وgo_router للتنقل حسب الدور.

يشمل المشروع:
- أربع تجارب: المشرف العام، صاحب المولد، قارئ العدادات، والمشترك.
- تعدد المولدات وفصل البيانات وصلاحيات الوصول بقواعد Firestore.
- تسجيل بالبريد وكلمة المرور، تحقق بالبريد، واستعادة كلمة المرور.
- تسجيل المولدات والمشتركين ومراجعة طلبات الانضمام وحالاتها.
- إسناد العدادات، جولات قراءة قابلة للاستئناف، وإصدار فواتير بإعدادات محفوظة.
- دفعات كاملة وجزئية ضمن الفوترة الدورية، ومراجعة الاعتماد والرفض، ومتابعة الذمم والمصروفات.
- حالة تشغيل وجدول مسجلان في التطبيق، وشكاوى وتنبيهات داخلية ومحلية.
- هوية بصرية متسقة، عربية RTL، ووضعان فاتح وداكن.
- اختبارات للحسابات والتوجيه والصلاحيات والواجهات.

راعيت استخدام Firebase Spark ضمن حصصه، دون SMS أو Storage أو Cloud Functions في المسارات الحالية. هذا لا يعني تشغيلًا مجانيًا بلا حدود.

الصور لواجهات Flutter الفعلية ببيانات تجريبية. المشروع يُعرض كدراسة حالة تطوير، دون ادعاء نشره في المتجر أو اعتماده من جهة رسمية.

المهارات: Flutter، Dart، Firebase، Riverpod، go_router، تصميم واجهات عربية، RTL، اختبارات التطبيقات.

## Upwork — Short project description

Arabic-first Flutter app connecting generator owners, residents, meter readers and a super admin. Built with Dart, Riverpod, go_router and Firebase. Features include tenant-scoped access, email authentication, approval workflows, resumable reading rounds, exact billing, reviewed partial payments and finance summaries. Consistent light/dark UI with automated auth, billing and rules tests. Screens show fictional demo data; no production usage or store-release claims.

## Upwork — Extended case study

**Problem:** Neighbourhood generator services need a clear way to coordinate operation status, meter readings, invoices and payment follow-up across different users.

**Implementation:** An Arabic-first Flutter application with four role-specific experiences. Firestore data is scoped by generator, with rules restricting access according to membership and role. Email/password authentication includes verification and email-based password reset.

The billing workflow supports assigned meter readers, resumable round preparation, fixed-point calculations, frozen invoice settings, reviewed full/partial payments in cycle billing, and summaries of receipts, receivables and expenses. The visual system includes bundled Arabic typography, RTL layouts and matching light/dark themes.

**Engineering focus:** Riverpod state management; go_router role guards; Firebase Auth and Firestore integration; reusable input/sheet components; regression tests and local emulator rules tests.

**Constraints:** Spark quotas are finite. Current flows do not depend on paid hosting, SMS, Firebase Storage or Cloud Functions. In-app/local alerts are not guaranteed remote push when the app is closed. Sharing uses the Android system share sheet, not automated WhatsApp delivery.

**Presentation:** Actual Flutter widget renders using fictional sample data, not photographs from a physical device. This is a development portfolio case study, not a claim of commercial adoption or an app-store release.

Skills: Flutter; Dart; Firebase; Riverpod; Mobile UI Design.
